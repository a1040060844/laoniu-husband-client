# 第二阶段 B：真实使用前管理能力说明

本文档对应 `laoniu-husband-miniprogram` 的第二阶段 B，目标是让体验版从“业务闭环可跑”推进到“真实老哥老妞日常使用可管理、可追踪、可修正”。

## 1. 本阶段新增能力

- openid 白名单与开发身份切换配置。
- 登录页开发调试入口：查看当前 openid、role、nickname，并可重绑身份。
- 老哥端任务状态筛选：全部、待开始、进行中、待确认、已完成、已失败。
- 老妞端任务状态筛选：今日待处理、待确认、进行中、已完成、已失败。
- 任务卡片补充创建时间、提交时间、确认时间。
- 任务详情页补充完整任务信息、奖励信息、状态与操作错误提示。
- 钱包流水：零花钱奖励、人工调整、卖身奴隶暂停都会写入 `logs`。
- 经验/等级流水：任务经验、直接升级、手动调整都会写入 `logs`。
- 权益记录：申请、批准、驳回都会写入 `logs`。
- 卖身奴隶状态增强：原因、恢复条件、指定恢复时间。
- 云函数统一错误格式：`ok/errorCode/message`。

## 2. 数据库集合变化

本阶段没有新增数据库集合，继续使用：

- `users`
- `profile`
- `tasks`
- `rights`
- `logs`

`logs` 新增分类：

- `wallet_ledger`: 钱包流水
- `exp_ledger`: 经验/等级流水
- `right_record`: 权益申请与审批记录
- `role_rebound`: 开发模式身份重绑记录

## 3. 配置 openid 白名单

前端显示与开发入口配置在：

```ts
// laoniu-husband-miniprogram/src/config/access.ts
export const ACCESS_CONFIG = {
  enableDevRoleSwitch: true,
  husbandOpenid: "",
  wifeOpenid: "",
};
```

云函数强校验建议使用云函数环境变量：

- `HUSBAND_OPENID`: 老哥 openid
- `WIFE_OPENID`: 老妞 openid
- `ENABLE_DEV_ROLE_SWITCH`: `true` 或 `false`

真实体验前建议：

```text
HUSBAND_OPENID=老哥真实 openid
WIFE_OPENID=老妞真实 openid
ENABLE_DEV_ROLE_SWITCH=false
```

如果开发身份切换关闭，非白名单 openid 会收到：

```text
当前微信暂未获得访问权限
```

## 4. 开启/关闭开发身份切换

前端入口：

```ts
// src/config/access.ts
enableDevRoleSwitch: true
```

云函数强校验：

```text
ENABLE_DEV_ROLE_SWITCH=true
```

正式体验建议两处都关闭：

```ts
enableDevRoleSwitch: false
```

```text
ENABLE_DEV_ROLE_SWITCH=false
```

## 5. 测试任务筛选

1. 老妞登录，发布多个任务。
2. 老哥登录，分别执行“开始执行”“提交完成”。
3. 老妞确认、驳回或判失败几个不同任务。
4. 在老哥端“任务”页切换：
   - 全部
   - 待开始
   - 进行中
   - 待确认
   - 已完成
   - 已失败
5. 在老妞端“任务”页切换：
   - 今日待处理
   - 待确认
   - 进行中
   - 已完成
   - 已失败

每个筛选为空时应显示空状态文案。

## 6. 测试钱包流水

1. 老妞发布一个零花钱奖励任务。
2. 老哥提交。
3. 老妞确认。
4. 老哥端进入“圣旨”页，查看“钱包流水”。
5. 老妞端进入“裁定”页，查看“钱包流水”。
6. 老妞手动调整零花钱，再次查看钱包流水。

钱包流水写入 `logs`，类型为 `wallet_ledger`。

## 7. 测试经验流水

1. 老妞发布一个经验奖励任务。
2. 老哥提交。
3. 老妞确认。
4. 老哥端进入“圣旨”页，查看“经验流水”。
5. 老妞端进入“裁定”页，查看“经验流水”。
6. 老妞手动调整经验或等级，再次查看经验流水。

经验流水写入 `logs`，类型为 `exp_ledger`。

## 8. 测试权益申请审批

1. 老哥端进入“权益”。
2. 选择一个已解锁且非冷却的权益，提交申请。
3. 老妞端进入“权益”。
4. 查看权益申请。
5. 分别测试批准和驳回。
6. 批准后确认权益进入冷却。
7. 驳回后确认不会进入冷却。
8. 双方查看“权益记录”。

权益记录写入 `logs`，类型为 `right_record`。

## 9. 测试卖身奴隶恢复

1. 老妞端进入“裁定”。
2. 进入“资料调整”。
3. 开启“卖身奴隶状态”。
4. 填写原因。
5. 选择恢复条件：
   - 手动恢复
   - 满 100 EXP 后恢复
   - 到指定时间恢复
6. 保存。
7. 老哥端确认显示卖身奴隶原因和恢复条件。
8. 权益申请应不可用，零花钱显示暂停。
9. 恢复时关闭卖身奴隶状态并保存，或在满足 EXP/时间条件后进入页面触发检查。

当前没有后台定时器；自动恢复采用“进入页面或调用 profile 时检查”的方式。
